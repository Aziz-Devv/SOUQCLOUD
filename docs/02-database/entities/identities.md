# Database Entity: Identities (`auth.users` & Synchronization)

## 1. Purpose & Authority Boundary

Authentication credentials, password hashes, OAuth tokens, and sessions are managed exclusively by **Supabase Auth** in the private `auth.users` table. The application database maintains a corresponding profile in `public.users`.

> **CANONICAL IDENTIFIER INVARIANT**: The canonical identifier for any user across the entire platform is the UUID generated by Supabase Auth (`auth.uid()`). A duplicate or competing identity system must never be constructed.

---

## 2. Synchronization Pipeline & Email Integrity

Two database triggers maintain 1:1 synchronization between `auth.users` and `public.users`:

### 2.1 Trigger 1: User Signup Sync (`on_auth_user_created`)
```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.users (id, email, full_name, avatar_url, created_at, updated_at)
  VALUES (
    NEW.id,
    NEW.email,
    COALESCE(NEW.raw_user_meta_data->>'full_name', ''),
    NEW.raw_user_meta_data->>'avatar_url',
    NEW.created_at,
    NEW.created_at
  )
  ON CONFLICT (id) DO UPDATE
  SET email = EXCLUDED.email, updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

### 2.2 Trigger 2: Email Update Sync (`on_auth_user_email_updated`)
```sql
CREATE OR REPLACE FUNCTION public.handle_user_email_update()
RETURNS TRIGGER AS $$
BEGIN
  IF OLD.email IS DISTINCT FROM NEW.email THEN
    UPDATE public.users
    SET email = NEW.email, updated_at = NOW()
    WHERE id = NEW.id;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_email_updated
  AFTER UPDATE OF email ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_user_email_update();
```

---

## 3. Email Invariant
`auth.users.email` is the canonical authentication email. The `on_auth_user_email_updated` trigger guarantees that `public.users.email` remains strictly synchronized on all email change events.
